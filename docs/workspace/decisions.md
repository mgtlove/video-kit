# Decisions

One line each, with the reason, so they are not re-argued. Add to the end.

- 2026-10-01: Two repos, `video-kit` (product) and `video-reference` (research), side by side under `~/Developer/video/`, public, MIT; no org, no project board, no shared-tooling repo. For one person the shared rulebook moves inside the kit.
- 2026-10-01: Plain JavaScript, Node 18+, npm workspaces, no build step. Playwright with the installed Chrome (`PW_CHANNEL=chrome`); nothing downloads a browser.
- 2026-10-01: The command is `vkit` (was `vk` for a day). The page namespace stays `window.VK`.
- 2026-10-01: A video is a folder made by `vkit new`; the engine is copied in at its version (`rig/engine/VERSION`) so a video opens from disk and never changes under its owner. `vkit upgrade` moves it.
- 2026-10-01: Everything is a function in `packages/core`; the CLI, the plugin, the MCP server and any app are thin shells. Four adapters (voice, render, script, hosting), one file each, local implementations first.
- 2026-10-01: One layout: the screen at native pixels fills the frame, the explanation is a card that places itself beside the element it names, the camera is clamped to the frame and never under scale 1. The older inset-with-a-rail layout is not carried.
- 2026-10-01: Looks, patterns, rules and brands are data files made from the reference by `vkit sync-reference`; the menu reads them; no list is typed into a skill.
- 2026-10-02: The research moved into `video-reference` as it stood (seven creator studies with the deep pass, 96 craft rules, 35 patterns, seven look packs, six library studies, licences), with product and company names removed and paths pointed at `video-kit`; it is Matthew's own work, written with him, about public videos and standards. The earlier plan to rewrite it note by note was dropped as wasted effort.
- 2026-10-01: AWS enters as adapters (cloud render, Polly) when they earn their place; no app, database or auth before a non-terminal user exists.
- 2026-10-01: Matthew keeps working with the current chat until the product is more mature; a dedicated Claude project comes later, seeded from `claude/new-project-instructions.md`.
- 2026-10-02: Recreated apps are their own folders, not part of any video and not in the kit: `~/Developer/video/apps/<family>/<tool>/` with `app.json`, `tokens.css`, `states/` (one HTML fragment per captured state), `captures/` and `manifest.csv`. One app is what a learner would call "the tool" (per AWS service, plus `console` and `cli`); a state is one screen in one condition; ten to thirty states per app, split by area past that. A video names its app in `video.json` and the states it uses are copied in at build time, like the engine, so a finished video never changes when the app moves on.
- 2026-10-02: App repos are private, one per app family (`video-apps-aws`, later `video-apps-langchain`), each cloned into `apps/<family>/`; nothing from one family sits in another's repo. The kit only ever looks for `apps/<family>/<tool>/app.json`, so splitting an app into its own repo later costs the kit nothing. `video-kit` and `video-reference` stay public; the apps and the twins are the method and stay private.
- 2026-10-02: Three kinds of video, and the engine does not care which: whiteboard or theory (no screen), one-off screen (built inline from a couple of captures, as the starter does), app-backed (`vkit new --app aws/bedrock`). `vkit app extract` lifts an inline screen into an app the day it is needed twice; nobody builds an app ahead of need. The starter stays self-contained so `vkit new` works from a bare clone; the app-backed path has its own small example app inside the kit.
- 2026-10-02: Recreate from your own captures, cite each, never invent a control. That is the rule for every recreated screen; there is no rule against recreating a product. The separate rule that nothing is copied from an employer's or client's repository stands; it is about files, not screens.
- 2026-10-02: Fidelity is a measurement: `vkit check` renders each state and compares it with its capture at the same size, a structural similarity at reduced size and a side-by-side image. The image is what a person judges; the number is the trend; the threshold is set after looking at a dozen, not asserted first.
- 2026-10-02: The paid-call rule stays (no paid service without a recorded go-ahead; Matthew wants to see it and approve, not be blocked). The mechanism changes when the adapters land: each adapter prints the cost of a batch and stops for a yes; the guard hook's `--approved` rule goes at that point, not before.
- 2026-10-02: The twin (a learner clicks through the same app states, `flows.json` says which click shows which state, every unbuilt control shows one notice) is its own roadmap step, last, after the app folder exists. Its runner is generic and may live in the public kit; every twin's content is private.
- 2026-10-02: Roadmap order after the renderer: 5a app folder and `screen()`, then 4 strokes and the pointer (they target elements inside states, so the state format comes first), then 6 checker with fidelity, 7, 8, 9, 10 (the sample video is also the first real app), 11, 12 twin.
- 2026-10-02: Proofs run on the Mac's Chrome; quick checks may run anywhere with a Chromium. `npm test` runs its files one at a time because the playback proof is a real-time measurement.
- 2026-10-02: `manifest.csv` is the one list of an app's states (the design note had it in `app.json` too); people edit the CSV, so it wins. An app has `tokens.css` (palette and faces) and `screen.css` (structure), both scoped to `#mock`: the structure is as much the recreated product as the colours, and one file beats copying it into every state.
- 2026-10-02: The engine call is `state(id)`, not `screen(id)`: `window.screen` is the browser's display object and a page global with that name is a trap.
- 2026-10-02: The checker's numbers are copied, never retyped: `vkit sync-reference` copies `video-reference/craft/rules.json` into the kit with its commit; the rail and caption-band rows are marked not applicable because the kit has one full-frame layout and captions as a sidecar. A rule the checker cannot measure yet is reported as not measured with where the number lives; a silent pass is a lie.
- 2026-10-02: Fidelity is structural similarity at 960x540 grey over windows that have structure (variance at least 4), with the coverage reported; flat ground would otherwise score 1.0 whatever was done to it (a 12 px shift with blur measured 0.91 over all windows and 0.52 over structured ones). Reported, not judged, until a dozen real captures have been looked at.
- 2026-10-02: A flash is a reversal: a pair of opposing luminance changes of 10 percent or more (WCAG 2.3.1); a fade in one direction over several frames is one transition. The first count took a 0.6 s fade to a white screen for four flashes.
- 2026-10-02: The starter's highlight is a burnt orange (`#d4561e`, 4.1:1 on the stage and 3.7:1 on a white screen) because a stroke has to hold 3:1 on whatever it sits on; the brighter orange measured 1.65:1 on the screen. Read text in the starter sits at 54 px or is marked `data-decor`; the explanation card's body is 54 px.
- 2026-10-02: A look pack is applied as tokens (`rig/look.css`, `--look-*`) that `theme.css` reads after the brand and before its defaults; no look renders identically and a brand wins. Where a pack's colours meet the kit's layout, the contrast rules decide, not taste: stage text takes the paper colour when ink cannot hold 4.5:1 on the ground; the stroke is the first of ink then accents that holds 3:1 on both the ground and a white screen; a kind colour under 3:1 on the card falls back to the card's ink; the explanation card over a white screen is the first of paper, ink, ground that holds 3:1 on white. Each choice is written into `look.css` as a comment.
- 2026-10-02: Type families stay classes in the packs and map to system stacks in `looks/faces.json`; no face is downloaded or shipped until it has a licence row (OFL or an explicit web or app licence). A render is therefore pixel-identical per machine, not across machines, which the proofs already assume.
- 2026-10-02: `vkit measure` makes the clips the clock: exact lengths to two decimals into the `PARTS` line and `video.json.parts`; look, tone, patterns and voice lock from then on because each would re-time the video; `vkit look` refuses a change while locked. A missing clip writes nothing.
- 2026-10-02: An accent, for the accent-share rule, is a colour that differs from both the ground and the text colour by more than the match distance; a kind colour that fell back to ink is not one.
- 2026-10-02: A brand is applied as tokens too (`rig/brand.css`, `--brand-*`, read before the look), and the mark and the banner are tokens the engine turns into elements and minor beats at boot, so no brand means no elements and a byte-identical render. Their placement (a corner inside title safe, a bottom edge above the caption band) is the engine's and the rules', not the brand's; `always` hides over a recreated screen so the product is never covered, `watermark` is the one that stays. A brand's colours are written as given and measured, never changed: `vkit brand --check` reports each against the surface it sits on, including the recreated screen's own ground, because a teal that held 3.3:1 on white measured 2.96:1 on the placeholder screen's lavender.
- 2026-10-02: The kit ships a neutral `brands/example` and an empty `brands/TEMPLATE`; Matthew's own brand (swab.the.stack) is not developed yet and will live outside the public kit when it is.
- 2026-10-02: `vkit menu` is the one front door to `video.json.menu`. The items, their words and their fixed options are `menu-defaults.json`; the growing lists are read from `looks/index.json`, `brands/`, `patterns/index.json` and the apps folders; a video records answers only (value, from, chosen_on, note). Choosing a look or a brand in the menu runs `vkit look` or `vkit brand`, so the record and the rig cannot disagree. Layout offers `full` only and says the classic inset layout is not built; voice offers only what the renderer does (clips or none, sidecar captions or none, no music bed).
- 2026-10-02: The text of a brand mark or banner is decoration (`data-decor`): the voice never depends on it, so the 54 px read-text floor does not apply, but title safe and 4.5:1 still do.
- 2026-10-02: Progress is a core contract, not a print: every slow function takes `opts.progress(step, done, total, note)` and the shell draws it (the CLI: a bar that rewrites one line on a terminal, plain lines every five seconds in a pipe, `VKIT_QUIET=1` for none). The proofs report every 20 seconds. The MCP server and the cloud renderer will read the same calls; nothing in core knows which shell is listening.
- 2026-10-02: A skill never carries a list the kit can print: the plugin's typed list of menu items is out of the repo (kept on Matthew's Desktop), and `video-menu` reads `vkit menu --explain` and writes `vkit menu --set`. `plugin.test.js` holds every skill to the commands that exist: a `vkit` command, a flag or a menu item named in a skill that the CLI does not have fails the suite.
- 2026-10-05: A surface that read text sits on is opaque when anything sits behind it. The explanation card's 93 percent panel let the screen's values show under its words, and the contrast rule could not see it because it measures the surface, not what shows through; `surface-opaque` now fails that by element, alpha and what is behind. The concept cards' 3 percent fill stays: nothing sits behind them but the stage.
- 2026-10-05: The explanation card keeps clear of the named element's neighbours (its siblings, and every leaf element with an id in the recreated screen), not only of the element itself: the sides of the element first, then the sides of the group, then the side that covers least; an author's `side` still wins. Found by the frames skill looking at stills one by one, which the contact sheets had not shown; `docs/FINDINGS.md` holds what the frames show and the checker does not, until each is fixed.
- 2026-10-05: A camera frame over a recreated screen starts at a chrome edge (past the side menu, below the top bar) or shows the chrome whole; a cut label is a framing fault even when no rule measures it. The starter's part 2 offsets are measured from `pos()`, not guessed.
- 2026-10-05: A proof that compares two outputs passes when both are wrong the same way. The seek-equals-playback proof held at 0 pixels for four steps while no stroke ever drew in a rendered frame, because the seek's bake and the live transition failed alike; a person watching the MP4 saw it in a minute. Every step's landing now includes someone watching the output, and a fault seen that way goes into `docs/FINDINGS.md` like any other.
- 2026-10-05: Anything that looks hand drawn is drawn: a stroke that appears whole is a fault, not a style. The draw time is the look's (`--stroke-draw`, 0.6 s in the house theme); whether that reads as drawing at the viewer's pace is judged on the sample video.
- 2026-10-05: A stroke is measured against each surface it sits on, never against an average of them: the pixels beside each drawn stroke pixel, bucketed by colour, the worst surface with 8 percent or more of them. An average of a paper card and a dark ground is a grey the stroke never touches; it read 2.93:1 for a stroke holding 3.6:1 and 4.5:1 on the real surfaces.
- 2026-10-05: The capture is a walkthrough document, not a folder of pictures: one `.docx` with a heading per step, a line saying what was done, the screenshot under it and a note for what a still cannot carry. The document carries the order and the words a folder cannot, it is what a person with the tool naturally writes, and it is read with its pictures in place. The agent never captures a product screen itself; the brief (`docs/CAPTURE.md`) goes to whoever has the tool. The same brief serves a one-off screen and a recreated app.
- 2026-10-05: `vkit capture` checks the shape of what arrived and never its content: PNG; 1920x1080, or 3840x2160 as a 2x capture, any other 16:9 at or above 1920 wide a warning, anything else a fail; no two pictures the same; every picture under a heading with a line before it. A green run says the files are usable, not that the screens are right or clean; the pictures are opened and read, every one, by the `video-capture` skill or a person. Pixels are never touched; a 2x capture stays 2x and is recorded.
- 2026-10-05: No browser is a plain stop, not a hang and not a download: with no `PW_CHANNEL` and no bundled Chromium, every browser command fails in under a second with `no browser: set PW_CHANNEL=chrome`, before Playwright can suggest `playwright install`, which the guard would block and an agent might loop on.
- 2026-10-05: For a web or browser-backed app, the capturer reads the page's own values (computed colours as hex, the font stack and sizes, region sizes, exact labels) and writes them under the picture in the walkthrough document, so the recreated screen starts from measurements rather than from a picture read by eye. Numbers and words only: the product's HTML, CSS, JavaScript, icons and images are never pasted into the document or any repository; the screen is recreated, never copied.
